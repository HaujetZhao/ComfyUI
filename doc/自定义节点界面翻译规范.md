# 自定义节点界面翻译规范

给 ComfyUI 第三方节点做中文界面翻译时按本文操作。**下面"翻译面清单"逐项过，一项都别漏**（VHS 只做了前两项，KJNodes 后来又补了五项）。

## 翻译面清单（全部在 `locales/zh/`）

| 文件 | 键 | 译什么 |
|---|---|---|
| `nodeDefs.json` | 节点注册名 | `display_name`、`description`；`inputs.<参数名>.name`（参数标签）、`.tooltip`；`outputs.<索引>.name`（仅自定义了 RETURN_NAMES 的）、`.tooltip` |
| `settings.json` | 设置 ID（**点号换下划线**） | `name`、`tooltip`、`options`（下拉选项值） |
| `commands.json` | 命令 ID（**点号换下划线**） | `label`（快捷键设置、命令面板） |
| `main.json` | `settingsCategories` | 设置分组名 |
| `main.json` | `nodeCategories` | 分类树段名，**按 `/` 逐段独立查键**，只补官方 zh 没覆盖的段 |
| `main.json` | `dataTypes` | 输入/输出槽类型标签（IMAGE→图像），全局命名空间，只写自有类型 |
| `main.json` | `contextMenu` | 右键菜单项，**按原文整串查键**（含模板字符串展开后的每个变体） |
| `main.json` | `menuLabels` | 顶部菜单栏条目，**按标签整串查键**（含子菜单路径段） |

改完必须重启 ComfyUI 且界面语言设为中文才生效。

## 翻不了的（别浪费时间）

- 节点输入的**下拉选项值**（`lanczos` 等）：选项值即提交给后端的数据值，前端无翻译路径。
- DOM 硬塞的菜单项（`textContent` 直写）、菜单数组里的**纯字符串**项、子菜单 `title`：翻译钩子覆盖不到。
- 输出显示名仅在 `名 ≠ 类型` 时生效，纯类型输出走 `dataTypes`。

## 流程

1. **摸清注册面**：grep 前端 JS 的 `settings:`/`commands:`/`menuCommands:`/`getCanvasMenuItems`/`content:`，及节点类 `CATEGORY`；后端 `INPUT_TYPES`/`RETURN_NAMES` 用脚本真实导入导出（禁止静态 grep，动态注册会漏）。**纯前端节点**（不经 `NODE_CLASS_MAPPINGS`、由 `LiteGraph.registerNodeType` 注册的，rgthree 的 Fast Muter/Bookmark 等属此类）：前端会为它们合成 nodeDef 并走同一条翻译查找，nodeDefs.json 直接加键即可；键名清单从前端 `NodeTypesString` 之类常量里找，校验脚本要加白名单。
2. **导出权威清单**：`PromptServer.instance` 未初始化就塞 dummy（`prompt_queue` + `app.router.frozen`，不同插件要的字段不同）；目录名带横线的用 `spec_from_file_location` 加载。清单脚本样例：`my/dump_kjnodes_slots.py`、合并校验样例：`my/merge_kj_names.py`。
3. **翻译**：量大用子代理并行分片，prompt 里给足格式、术语表、官方译法查证要求（`E:\repos\ComfyUI_frontend\src\locales\zh\`）；导出脚本先自测（combo 参数的 `type` 是列表，进 set 会炸）。
4. **硬性校验**：nodeDefs 键 = `NODE_CLASS_MAPPINGS`、参数名 ⊆ `INPUT_TYPES()`、输出索引 < `RETURN_TYPES` 长度、settings/commands 键与源码注册 ID 零错配。多一个少一个都会回退英文。
5. **提交**：英文 commit message，按面分提交（settings / nodes+commands / names / 菜单）。

## 术语与风格

- 参考官方：`E:\repos\ComfyUI_frontend\src\locales\zh\nodeDefs.json`（先 grep 再译，model→模型、denoise→降噪、seed→随机种子、positive/negative→正面/负面条件）。
- 技术词保留英文：Wan、Flux、GGUF、LoRA、CLIP、T5、cfg、NAG、RoPE；官方保留原名的参数（cfg 等）**整个省略条目**，不写英文凑数。
- 隐藏系统参数（unique_id、extra_pnginfo、prompt）省略。
- 全角标点，tooltip 简洁不啰嗦；无原文依据不编造。

## 提 issue + PR（翻译完成后）

1. fork 上游仓库，`git remote add fork`，push 翻译分支。
2. **先查上游默认分支**：`gh repo view <owner>/<repo> --json defaultBranchRef`——PR 的 base 必须是它（VHS 的 `master` 是不接受 PR 的僵尸分支，真分支是 `main`）。fork 刚建好时 compare 会报"无提交"，等几分钟。
3. **先 issue 后 PR**：issue 写背景（为什么做、覆盖了什么、机制是官方 locales，零代码改动）；PR 正文引用 issue，列改动清单。**正文先写中文给用户审，通过后用英文提交**（gh 命令前挂代理 `export https_proxy=http://127.0.0.1:7899 http_proxy=...`）。
4. 纯新增 `locales/` 目录的 PR 风险最低；生成脚本不进 PR。
